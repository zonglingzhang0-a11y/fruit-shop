# 个人信息保护与合规说明

> 选题：**街边水果店临期果品动态定价与到店客流适配推送系统**
> 本文档说明系统的数据边界与合规立场，供报告"伦理与合规"章节直接引用，也可作为答辩问答的准备材料。
> 正文 **584 字**（第 1–4 节，脚本可核）；附录为核对材料，不计入正文字数。

---

## 1. 定位：决策辅助，不自动执行

本系统是水果店的临期定价**决策辅助**工具，不是自动定价系统。系统只做三件事：按批次剩余天数与库存生成候选折扣建议（仅取六个固定档，且不高于原价）、给出中文理由与期望销量、按品类偏好生成推送文案。**是否改价、是否发送、是否报废，一律由店主点击确认**——系统不自动改价、不自动淘汰批次、不自动群发消息。店主的每次采纳或改价都写入决策留痕表（`pricing_decision`），可追溯、可追责。因此，价格这一直接影响消费者权益的决定，责任主体始终是人，不是模型。

## 2. 数据最小化：存什么、不存什么

系统对会员只保留四类信息：会员号、昵称、**手机尾号（不超过 8 位）**、加入日期与推送开关；偏好只记品类、购买次数与最近购买日。**不采集人脸、位置、身份证件，不保存完整手机号、支付与银行卡信息**，不接入门店监控摄像头。系统中的"到店客流"是用历史成交笔数与去重会员数近似的**时段分布**，不是对顾客的识别追踪；未加入会员的顾客不留任何个人记录。

## 3. 推送：有频次上限、可退订

推送遵守两条硬约束：同一会员**每天最多 2 条**，且 **22:00 至次日 8:00 静默不发送**。系统发送前自动跳过超限与静默时段的消息并告知原因。会员可随时关闭推送开关或告知店主，**退订立即生效**，退订后不再进入任何目标人群；没有任何偏好记录的会员不会被单独推送，只看到不针对个人的全店文案。

## 4. 公平性：偏好只决定"发给谁"，不决定"卖多少钱"

品类偏好只用于排序"谁更可能感兴趣"，**绝不用于差别定价**：同一批次同一时点对所有顾客同价，不存在"熟客更贵"或"熟客更便宜"。定价建议的输入只有批次剩余天数、库存与时段需求，与个人身份无关，从源头避免价格歧视质疑。

## 附录 A. 承诺 → 实现对照（可逐字段核对）

| 本文档的承诺 | 落实到系统哪里 | 怎么验证 |
| --- | --- | --- |
| 只存手机尾号 | `member.phone_tail VARCHAR(8)`，**字段长度本身限制为 8 位** | 查表结构；全库搜索不存在全号字段 |
| 不存人脸/位置/身份证/支付信息 | 表结构中**不存在**此类字段；系统无摄像头接入 | 核对 `member`、`member_pref` 全部字段 |
| 不采集非会员顾客信息 | 全库无顾客标识字段；客流表只有小时级聚合计数 | 核对 `shop_traffic_hourly`：仅 `order_count`/`customer_count`（去重会员数） |
| 频次上限 | `app.push.daily-limit-per-member`（默认 2） | 同日对同一会员连发 3 次，第 3 次被跳过 |
| 静默时段 | `app.push.quiet-hours`（默认 22:00–08:00） | 置于静默时段发送，返回跳过且无新消息入库 |
| 退订立即生效 | `member.push_enabled` 开关 | 关闭后预览与发送的目标人群均不含该会员 |
| 不针对个人群发 | `push_log.member_id IS NULL`（群发行）；计划侧 `push_task.channel='GROUP_TEXT'` | 群发日志的 `member_id` 为空 |
| 推送不自动执行 | 计划与日志只能由 `POST /api/push/preview` / `POST /api/push/send` 写入；推送侧禁止任何定时任务 | 无人操作时 `push_log` 无新增、计划保持 `PLANNED` |
| 定时任务只做派生计算 | 临期扫描只写 `freshness`/`at_risk` 等派生列与日志，不写任何决策结果 | 定时任务跑一轮后 `pricing_decision`/`push_log`/`sales_record` 零新增 |
| 定价不自动执行 | 价格只能由 `POST /api/pricing/decisions` 写入 | 无人操作时 `pricing_decision` 无新增、价格不变 |
| 决策可追溯 | `pricing_decision` 含 `suggested_price`/`final_price`/`operator`/`reason`/`decided_at` | 查库字段非空 |

## 附录 C. 答辩预设问答

| 可能的质疑 | 回答要点 |
| --- | --- |
| "你们是不是在自动给顾客改价？" | 不是。系统写的是建议，改价必须店主点确认，`pricing_decision` 记录了他改成了多少——人机协同，人负责。 |
| "你们用摄像头统计客流吗？" | 不用。客流口径是历史成交笔数与去重会员数，`docs/01` 第 4.6 节有明确注释，报告里也是这么写的。 |
| "会员数据会不会泄露隐私？" | 只存尾号与品类偏好，没有全号、没有人脸、没有位置；退订立即生效，且频次有上限。 |
| "算法会不会歧视某些顾客？" | 偏好只参与"选谁收消息"，不参与"卖多少钱"；同一批次同一价，`docs/05` 第 4 节已写明这条边界。 |
| "未实现的合规环节是什么？" | 会员数据的**保留期限与删除机制**本次未实现，已作为局限性写入附录 B 的 C-05。 |
