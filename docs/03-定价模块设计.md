# 定价模块设计（阶段 2）

> 本文档回答三个问题：**模型怎么定价**、**凭什么说它比固定价和规则折扣好**、**这个结论在什么条件下才成立**。
> 配套文件：`scripts/pricing_model.py`（模型版）、`scripts/pricing_rule.py`（规则基线）、`scripts/evaluate_strategies.py`（评测台）、`release/evaluation-report.md`（自动生成的对比表与图）。
> 编写：队友 C（定价/评测）　依赖：`docs/01` 第 3 节业务规则、`docs/02` 仿真器假设、`data/seed/calibration/*.json` 真实数据校准。

## 1. 三个策略，只换定价函数

| 策略 | 代码 | 决策规则 | 角色 |
| --- | --- | --- | --- |
| **FIXED** | `make_fixed_pricing_fn()` | 永远原价，不打折 | 基线 1（现状：老板不降价） |
| **RULE** | `pricing_rule.py` | 剩余天数 + 库存压力两步打分，查表出折扣 | 基线 2（店主经验） |
| **MODEL** | `pricing_model.py` | 从历史估需求曲线，在候选档里选**含报废成本的期望收益**最大者 | 本项目方案 |

三者共用同一份候选折扣档 `{1.00, 0.90, 0.80, 0.70, 0.60, 0.50}`（`docs/01` 第 3 节），都不涨价，单品当天只挂一个价签（同单品多批次取最深折扣，先清最急的货）。

**为什么规则版故意写得朴素**：如果基线也去估弹性、算期望收益，对照实验就变成"我的模型 A vs 我的模型 B"，失去意义。`pricing_rule.py` 的决策表只有 9 行、全部可人工复核，这就是它作为基线的价值。

## 2. 规则基线（RULE）怎么做

两步打分，查表出折扣：

```
紧迫度 urgency    : 剩余 0 天→4, 1 天→3, 2 天→2, 3 天→1, ≥4 天→0
库存压力 pressure : 剩余比例 ≥70%→3, ≥50%→2, ≥30%→1, 否则 0
                    （只在 days_left ≤ 3 时才计入，否则刚到货的新批次会被误判成"压力最大"）
score = urgency + pressure (+1 若剩余寿命比例 ≤ 20%)
discount = SCORE_TO_RATE[score]     # {0:1.00, 1:0.90, 2:0.90, 3:0.80, 4:0.70, 5:0.70, 6:0.60, 7:0.50, 8:0.50}
```

两条硬护栏：① 刚到货未临期 → 原价；② 最后可售日且仍有货 → 至少 7 折。

自检：`& 'C:\Python314\python.exe' scripts/pricing_rule.py --selftest`（8 个典型场景 + 档位合法性 + 单调性 + 单品级取最深折扣）。

## 3. 模型版（MODEL）怎么做

### 3.1 需求模型：单品内去均值的对数线性回归

$$\log(\text{sold}_{i,t}) = \alpha_i + \beta_i \cdot \log\!\left(\frac{p_{i,t}}{\text{base}_i}\right) + \gamma_{\text{dow}(t)} + e_{i,t}$$

| 项 | 含义 | 估计方式 |
| --- | --- | --- |
| $\alpha_i$ | 单品固定效应（"这个单品天生好卖/难卖"） | 用估计出的 $\beta_i$ 与中心化后的 $\gamma$ 反算单品均值 |
| $\beta_i$ | **自身价格弹性**，预期为负 | 单品内去均值斜率，再向池化值**经验贝叶斯收缩** |
| $\gamma_{\text{dow}}$ | 周内效应（周一~周日） | LSDV 虚拟变量，中心化到均值 0 |
| 标准误 | cluster-by-item 稳健标准误 | 避免把单品内的相关性当成样本量 |

**收缩**：$\beta_i = \dfrac{n_i \cdot \beta_i^{\text{own}} + K \cdot \beta^{\text{pooled}}}{n_i + K}$，$K=40$，样本越少越向池化值靠。目的是防止某个单品只观测到 3 天就估出 −8 这种离谱弹性。

**护栏**：弹性裁剪到 $[-5.0, -0.05]$；单品可用观测 < 12 条时不单独估斜率，直接用池化值。

### 3.2 内生性与截断偏差：必须讲清楚的两条

> 这一节是答辩最可能被追问的地方。**两条偏差方向一致**，因此结论是"偏保守"还是"偏乐观"必须写明。

**（1）策略内生性 —— 历史价格是策略选出来的。**
前 60 天的价格由 RULE 决定：**库存压手、明天就到期的货才打折**。于是"低价"总是伴随"本来就更难卖的库存状态"，回归会把这份不利状态算到价格头上，使 $|\beta|$ **被低估**。
→ 处理：单品内去均值（固定效应估计），把"这个单品天生难卖"这一层吸掉。

**（2）缺货截断（右删失）—— 卖光那天看不到真实需求。**
某天断货时观测到的 `sold_qty` 被库存封顶，真实需求更高但看不见。而深折日最容易断货，于是**高需求点被系统性压平**，$|\beta|$ **再次被低估**。
→ 处理：`is_stockout=True`，或 `sold_qty ≥ 0.98 ×(期初库存 + 当日到货)` 的样本**整行剔除**；被剔除的比例记录在 `DemandModel.meta["n_dropped_stockout"]` 里，评测报告如实给出。

**（3）偏差方向的结论（重要）。**
两条偏差同向：$|\beta|$ 偏小 → 模型低估"打折能带来多少增量" → **打折偏保守、清货偏少**。
因此本评测里 MODEL 若赢，是**赢在偏保守的估计上，优势是下界**；若输，也不能说明模型思路错，只说明它在低估弹性时不够激进。**本报告的所有结论按"偏保守"解读。**

### 3.3 为什么不能直接用朴素回归 —— 用真实数据说话

`calib`（task-1）在 2023 数模 C 题**真实蔬菜流水**（46,595 条 单品×日，246 个单品）上跑了四种估计：

| 模型 | 弹性 | n | R² | 能否用于定价 |
| --- | --- | --- | --- | --- |
| 单品均值层（between） | **−0.982** | 246 | 0.406 | ❌ 衡量的是"均价高的单品本来就卖得少"，是横截面定位差异 |
| 朴素 pooled OLS（含常数项） | **−0.788** | 46,595 | 0.163 | ❌ 混了组间+组内，把弹性**高估**约 0.27（相对 FE 偏高约 50%） |
| **单品固定效应 + 周几/月份/趋势** | **−0.523** [−0.548, −0.498] | 46,595 | 0.108 | ✅ **主估计** |
| IV（工具 = ln 批发价） | **−0.366** [−0.397, −0.336] | 46,595 | 一阶段 F=58,946 | ✅ 稳健性对照 |

**教学价值在于**：朴素回归量到的主要是**组间成分**（单品均值 −0.982），不是价格效应；把真实弹性高估了约 50%。所以本项目**必须做单品内识别**，这也是 `pricing_model.py` 用去均值而不是直接 pooled OLS 的原因。

**仍然存在的不确定性（如实写，不编因果）**：组内 −0.523 与 IV −0.366 之间还差 0.16。IV 的排除性约束（批发价只通过零售价影响销量）本身可疑，无法进一步区分哪个更接近真相。这个区间就是弹性估计的**不确定性下界**。

**估计陷阱（团队自查记录）**：`calib` 早期报过一个 "+0.637，价格越高卖得越多" 的结果。复查发现是**回归漏掉常数项、强迫过原点**导致的设定错误——信号是 **R² 为负**。补上截距后正确值是 −0.788。本模块的 `naive_pooled_ols()` 用去均值实现（等价于含常数项），并在自检里断言 `R² ≥ -0.05`，把这个陷阱固化成了会失败的测试。

### 3.4 迁移警告：蔬菜 ≠ 水果

上面是**蔬菜按日清仓**的弹性。水果是标品（按个/盒）、保质期以天计、允许隔夜，需求应更平缓，真实弹性应更接近 0。因此把 $[-0.573, -0.316]$ 当作**上限参考**（即真实水果弹性可能比它更接近 0），而不是真值。

`pricing_model.py` 的 `elasticity_plausibility()` 会把仿真数据上估出的弹性与这个区间并列打印。**当仿真器的真值弹性明显超出该区间时，我们不做人工裁剪，而是把差异如实报告并解释**——理由是：裁剪等于把先验强加给一个"真值已知"的仿真世界，会让评测变成"我故意让模型估错"，反而不诚实。差异来源有三条可解释路径：① 仿真器把弹性设得比蔬菜数据更大（水果单件价格低、促销感知强）；② 计量口径不同（按个 vs 按 kg）；③ 固定效应后残余的内生性未完全消除。

### 3.5 决策：候选档枚举 + 有限期动态规划

朴素做法是"选让**今天**期望收入最大的折扣"，但那会**系统性地打得太浅**：今天没卖掉的货明天还能卖，明天卖不掉就报废。所以用倒推价值表：

$$W[0][q] = \max_d \left\{ p(d)\cdot \mathbb{E}[\min(\text{Pois}(\lambda_d), q)] - c\cdot(q - \text{卖出}) \right\}$$
$$W[k][q] = \max_d \left\{ p(d)\cdot \mathbb{E}[\min(\text{Pois}(\lambda_d), q)] + W[k-1][q - \text{卖出}] \right\}$$
$$\text{决策}(k, q) = \arg\max_d \{\cdots\}$$

- $k$ = 剩余可售天数，$q$ = 现存件数（整数离散化），$c$ = 进货成本
- $W[k-1]$ 就是"留到明天的机会价值"，**报废成本通过 $W[0]$ 里的 $-c\cdot(q-\text{卖出})$ 进入目标函数**
- $\mathbb{E}[\min(\text{Pois}(\lambda), q)]$ 用 log-pmf（`gammaln`）向量化精确计算，不用近似
- 折扣只在候选档里选，不做连续搜索（`docs/01` 第 3 节）

**单品级需求如何分摊到批次**：模型估的是"单品×日"的需求 $\lambda_i$，而库存落在具体批次上。按批次占单品当日可售量的份额分摊：$\lambda_b(d) = \lambda_i(d)\cdot q_b / Q_i$。得到的结果天然满足"同单品所有批次同价"（因为份额只影响数量、不影响 argmax 的形状）。

**已知近似**：单批次 DP 假设该批次在单品内的需求份额**保持不变**，不建模同单品多批次之间的互相蚕食。因为其他批次也在消耗，真实份额会随时间上升，所以这个近似对"留到明天"的价值**略微保守**。

### 3.6 学习节奏与退化保护

- **滚动重估**：每 5 天用"截至前一天"的观测历史重估一次（`--refit-every` 可调）。三个策略的**前 60 天都跑同一套 RULE 决策**，所以模型第一轮重估看到的历史，就是 FIXED/RULE 也看到的那 60 天，起点公平。
- **退化保护**：历史样本不足或价格无变化时，模型不静默返回原价（那会让 MODEL 退化成 FIXED、在评测里制造"两策略完全一样"的假象），而是**显式回退成规则折扣**并计数（`ModelPricer.n_fallback_days`）。回退天数会写进评测报告。

### 3.7 "不作弊"红线是代码里的一等公民

模型只允许读两类输入：`state["batches"]`（台账）与 `state["history"]`（已发生观测）。**真值参数（`base_demand`/`elasticity`/`hour_factor`）与未截断需求 `demand_qty` 一律不可访问**，由三处机制保证：

1. `_assert_no_truth_access()` 扫描输入对象的键/列名，命中黑名单**直接抛 `TruthLeakError`**（不是注释，是会失败的测试）；
2. `make_model_pricing_fn()` 在每次调用时对 `state`、`state["batches"]`、`state["history"]` 各扫一遍；
3. `evaluate_strategies.py` 只在**事后计分**时读 `day["demand"]` 算缺货率，该数据**不回流**给任何策略。

自检里有两项专门验证这条红线：混入 `elasticity` 或 `demand_qty` 时必须抛异常。

## 4. 评测协议

### 4.1 同源对照：三个策略只换定价函数

| 环节 | 做法 |
| --- | --- |
| 随机源 | 仿真器用 `PCG64([seed, day_index, hour, stream_id])` **预抽取**全部外生冲击，抽样格的形状与顺序只依赖 (day, hour, item)，**与策略选了哪个价无关** → 同一 seed 下三策略面对同一条消费者流（公共随机数 CRN） |
| 历史窗口 | 每个 seed 的前 60 天，三个策略**都用同一套 RULE 决策**（店主现状），第 60 天取 `sim.snapshot()` |
| 测试期 | 从同一快照 `restore()` 出发，各自跑 30 天；快照不含 `_truth` |
| 指标区间 | 只统计后 30 天测试期 |
| 种子 | ≥20 个（`--seed-base 20260701 --seed-step 101`） |

**同源性是被验证的，不是被声称的**：评测报告第 1 节逐种子列出
① 三个策略第 60 天的观测历史哈希是否一致、② sim 自带的 `state_hash()` 是否一致、③ `noise_fingerprint()`（预抽噪声矩阵指纹，只与 seed 有关）、④ **MODEL 与 FIXED 的进货量/到货批次数差异**。

第 ④ 条是 Lead 特别要求的**防作弊检查**：如果某个策略的损耗率优势来自"进货更少"而不是"卖得更好"，这两列会显著偏离 0。补货策略与定价无关，正常情况下差异应≈0。

### 4.2 指标口径（全部写死在 `evaluate_strategies.py`）

| 指标 | 口径 |
| --- | --- |
| **经营毛利**（主指标） | 收入 − 销售成本 − **报废成本** |
| 毛毛利 | 收入 − 销售成本（不扣报废，用于和会计口径对齐） |
| 损耗率 | 报废量 / 进货量（`docs/00` 第 4 节定义） |
| 缺货率 | 未满足需求 / 总需求 |
| 售出率 | 售出量 / (期初库存 + 当日到货) |
| 平均折扣深度 | 测试期各在售折扣系数的均值（1 − d） |
| **挂出折扣低于成本的占比** | 折后价 < 进货成本的挂出次数占比 ← **打穿毛利检查** |
| 平均剩余货值 / 期末库存 | 期末库存 × 进货成本 ← Lead 要求的**防作弊检查**（防止靠"少进货/不清货"刷损耗率） |
| 单笔客单价 | 收入 / 成交笔数 |

### 4.3 折扣下界的业务依据（来自真实数据校准）

`calib` 从真实加价率（中位 1.651）与品类损耗率派生出**保本折扣系数** $d = 1/(\text{加价率}\times(1-\text{损耗率}))$，落在 **0.63 ~ 0.79**（花菜类 0.732、花叶类 0.675、食用菌 0.676、辣椒类 0.628、茄类 0.672、水生根茎类 0.788）。

**也就是说 0.50 与 0.60 两档在蔬菜口径下已经跌破或贴近保本线。** 候选集按 `docs/01` 第 3 节保持 `{1.00…0.50}` 不变（这是冻结的接口契约），但评测必须回答一个问题：**模型版是不是靠无脑打到 0.50 换销量、把毛利打穿？**

→ 因此评测报告单列「折扣深度分布」图与「挂出折扣低于进货成本的占比」指标。若 MODEL 的深折占比显著高于 RULE 且毛利被拖低，必须在结论里点明而不是隐藏。

### 4.4 统计口径

- 每个 策略×指标 报 **均值 ± 标准差**（跨种子，`ddof=1`）；
- 策略间差异用**逐种子配对差**，报均值、标准差、min/max、2.5%/97.5% 分位、配对 t 检验 p 值；
- 同时报**逐种子胜负次数**（"20 个种子里 MODEL 赢了几个"），避免只看均值掩盖方差。

## 5. 结论与局限

> 具体数字见 `release/evaluation-report.md`（由脚本自动生成，本文件不手工抄数）。
> 结论句式固定为：**"在 XX 假设下，MODEL 相对 FIXED 把损耗率从 a% 降到 b%，经营毛利变化 c%（N 个种子，均值±标准差，范围…）。"**

### 5.1 假设边界（结论只在这些条件下成立）

1. 数据来自**自研仿真器**，不是真实门店流水；需求函数与参数分布是我们设定的。
2. 需求形式为常弹性、单品之间**无交叉价格效应**（黄瓜打折不会抢苹果的客人）。
3. 补货策略对三个策略**完全相同**，本评测隔离的是"定价"这一个变量。
4. 评测**关闭了推送**（`promo_lift ≡ 1`），收益不含推送带来的增量客流。
5. 消费者同质、无策略性等待（不会"知道明天更便宜所以今天不买"），无囤货。
6. 每种子只有 30 天测试期，季节性/节假日未建模。

### 5.2 局限（至少 3 条）

1. **仿真自证风险（最重要）**：结论只在"我们自己的仿真器假设"下成立。仿真器的需求函数本身就是"对价格敏感、对剩余天数不敏感"的形态，模型定价天然占优；换一台仿真器结论可能变化。缓解方式是①用公开真实数据校准参数、②明确列出假设边界、③如实报告模型没赢的指标与种子——**但不能声称这是真实门店的因果结论**。
2. **弹性估计的内生性与截断偏差**：两条偏差同向，都让 $|\beta|$ 被低估，使 MODEL 打折偏保守。因此优势是**偏保守的下界**（详见 3.2、3.3）。
3. **批次粒度简化**：真实店主不会逐箱登记，本评测按"品类+到货日"合成批次；批次级 DP 还假设单批次需求份额不变，未建模同单品多批次之间的互相蚕食。
4. **推送环节未纳入本评测**：`docs/00` 的"客流适配推送"是独立链路，本报告不含推送增量。
5. **单店、单场景、30 天**：未覆盖节假日、天气、竞品降价、供应链断货；也未建模顾客对频繁变价的信任损耗（真实店里天天打折会伤价格锚点）。
6. **成本与损耗参数是区间估计**：公开数据是蔬菜（散称、当天出清），迁移到水果（标品、可隔夜）只保留了"损耗率"概念与量级，数值不完全可比。
