## 系统架构

> 系统架构

| 层级 | 组件 | 技术 / 职责 | 说明 |
|---|---|---|---|
| 客户端 | 店主管理后台 | Vue3 网页 | 入库、临期看板、定价确认、推送管理 |
| 客户端 | 顾客端 | H5 特价页与消息 | 查看特价品、接收站内消息 |
| Spring Boot 后端 | 批次库存 | 入库与销售扣减 | 按批次记录库存，销售时先进先出扣减 |
| Spring Boot 后端 | 临期扫描 | 每小时定时任务 | 扫描批次，判定是否有卖不完的风险 |
| Spring Boot 后端 | 定价确认 | 店主接受或修改 | 展示定价建议和理由，记录店主处理结果 |
| Spring Boot 后端 | 推送任务 | 选时段选人群 | 按客流高峰和会员偏好安排推送 |
| 底层服务 | MySQL | 批次、流水、建议 | 业务数据存储 |
| 底层服务 | 定价引擎 | Python 需求估计与优化 | 独立服务，供后端调用 |
| 底层服务 | 本地大模型 | 生成推送文案 | 独立服务，供后端调用 |
| 主流程：批次库存 → 临期扫描 → 定价确认 → 推送任务 → 销售数据回流 |  |  |  |

## 数据库表

> 数据库表（核心：按批次管库存）

| 表 | 关键字段 | 作用 |
|---|---|---|
| product | 品类、单位、标准保质期、原价 | 商品档案 |

## 临期判定

> 临期判定指标

| 指标 | 计算方式 | 说明 |   |
|---|---|---|---|
| 新鲜度 | 剩余天数 ÷ 标准保质期 | 越低越接近到期 |  |
| 预计可售天数 | 剩余库存 ÷ 近几天的日均销量 | 按现价卖完库存需要的天数 |  |
| 有风险 | 预计可售天数 > 剩余天数 | 按现价卖不完，触发定价建议 |  |
| 示例计算（香蕉） |  |  |  |
| 蓝色数字为输入，可直接修改；黑色为公式，自动计算。 |  |  |  |
| 项目 | 数值 | 单位 | 备注 |
| 剩余天数 | 2 | 天 | 输入（来自示例） |
| 剩余库存 | 30 | 斤 | 输入（来自示例） |
| 日均销量 | 9 | 斤/天 | 输入（来自示例） |
| 标准保质期 | 5 | 天 | 输入；假设的示例值，原回答未给出，请按实际品类修改 |
| 新鲜度 | 0.4 |  |  |
| 预计可售天数 | 3.33333333333333 | 天 | 公式：剩余库存 ÷ 日均销量 |
| 到期前预计销量 | 18 | 斤 | 公式：不超过剩余库存 |
| 预计报废量 | 12 | 斤 | 公式：剩余库存 − 到期前预计销量 |
| 是否有风险 | 有风险 |  |  |

## 定价引擎

> 定价引擎（模型版）

| 步骤 | 名称 | 内容 |
|---|---|---|
| 1 | 估计需求 | 用历史流水回归出“折扣每加深一成，销量增加多少”，同时加入小时和星期的影响，按品类分别拟合。 |
| 2 | 枚举候选折扣 | 原价、9 折、8 折，一直到 5 折，分别预测到期前能卖多少斤，上限是剩余库存。 |
| 3 | 选收入最高的 | 进货成本已经花出去，目标是让剩余库存的总收入最大，而不是每斤都赚钱。 |
| 4 | 加约束 | 店主设最低折扣线，每天最多调价两次，避免价格乱跳。 |
| 5 | 输出理由 | 例如“按现价预计卖 18 斤，8 折预计卖 27 斤，收入更高”。店主可以接受、修改或拒绝，处理结果都记录下来。 |
| 对照组：规则版（按新鲜度和库存压力分档打折）保留，用于和模型版比较。 |  |  |

## 推送

> 推送设计

| 要素 | 设计 |
|---|---|
| 时机 | 从 traffic_profile 找到下一个高峰，提前 30 到 60 分钟推送；已经到最后一天的批次立即推。 |
| 人群 | 近期买过该品类且同意接收的会员，每人每天最多一条。 |
| 文案 | 后端把品类、折扣、截止时间传给本地模型，生成一段短文案，店主确认后发出。 |
| 效果 | 记录打开率，以及推送后几小时内是否买了该特价品。 |

## 仿真与评测

> 仿真与评测

| 项目 | 内容 |
|---|---|
| 仿真器 | 每小时按该时段的平均客流随机生成到店人数，每位顾客的购买概率随价格和新鲜度变化，连续跑 30 天。 |
| 对比策略 | 固定价格、规则版、模型版，使用同一组随机种子。 |
| 评价指标 | 损耗率、售罄率、毛利。 |
| 要避免的坑 | 如果仿真器的需求公式和定价模型用的是同一个，模型版必然赢，结论没有意义。 |
| 应对办法 | 仿真器的参数从公开数据拟合，并加入噪声或换一种函数形式；也可以留出一段真实流水做回测。 |
