## 1. 总体架构

```
┌──────────────────────────── 店长/店员工作台 (Vue3 + Vite) ────────────────────────────┐
│  临期清单 │ 定价建议与确认 │ 推送预览与发送 │ 批次入库 │ 效果看板                      │
└───────────────────────────────────┬──────────────────────────────────────────────────┘
                                    │ REST /api/**
┌───────────────────────────────────▼──────────────────────────────────────────────────┐
│ Spring Boot 3.5 后端                                                                  │
│  batch 入库与批次台账 │ pricing 定价建议与决策记录 │ member 会员与偏好                │
│  traffic 时段客流统计 │ push 站内消息与文案       │ sales 销售回流与效果统计          │
└──────────────┬─────────────────────────────────────────────┬─────────────────────────┘
               │ MyBatis-Plus                                │ 读取定价建议 / 写回决策
┌──────────────▼──────────────┐                ┌─────────────▼─────────────────────────┐
│ H2（MySQL 兼容模式，演示）   │                │ Python 定价与评测模块                  │
│ schema-h2.sql / schema-mysql │                │ 规则版 + 模型版 + 评测脚本             │
└──────────────────────────────┘                │ 产物：data/seed/pricing_*.json        │
                                                └───────────────────────────────────────┘
```

**为什么定价算法在 Python 侧、后端只读结果**：算法迭代（回归、枚举、评测）与数据分析共用 pandas/scipy 生态；把它写进 Java 会把调试成本翻倍，而本项目算法本身并不复杂。收尾期若时间富余，再包装成 FastAPI 微服务（见 `docs/00` 第 2 节）。

## 3. 核心业务规则（写死实现，不要各处重复）

1. **剩余可售天数**
   `days_left = floor((expire_date - biz_date) / 1天)`；批次到货当天 `days_left = shelf_life_days`。
2. **临期判定**
   `days_left <= app.pricing.near-expiry-days`（默认 2 天）→ 进入临期清单，按 `days_left` 升序排列。
3. **定价建议的候选折扣档**
   默认候选集合：`{1.00, 0.90, 0.80, 0.70, 0.60, 0.50}`（相对原价），算法在候选里挑，不做连续搜索。
4. **不建议涨价**：`suggested_price <= original_price`，即折扣系数 `<= 1.0`；促销目标是清库存，不是提价。
5. **最低折扣线（v2，参考架构《定价引擎》第 4 步）**：折扣系数不得低于 `app.pricing.min-discount-rate`（默认 `0.60`）。
   对 FIXED/RULE/MODEL **全部生效**，店主改价路径同样校验（低于底线返回 400 并告知"本单最低可售 ¥X"）。
   被底线拦住时 `price_floor_hit=true`、`raw_discount_rate` 记录原始档位，理由里说明"本可以更低，被底线拦住"。
6. **每日调价上限（v2）**：同一批次每天最多调价 `app.pricing.max-adjust-per-day`（默认 `2`）次。
   "一次调价"= 生成一条建议 **或** 店主实际改价一次；按建议价成交不算；幂等重跑不算。超限返回 400 并说明是第几次。
7. **推送频次**：同一会员每天最多 `app.push.daily-limit-per-member` 条（默认 2）；静默时段 `app.push.quiet-hours` 内不发送。
   额度按 **`push_log` 中真正送达的行**（`member_id` 非空且 `skip_reason` 为空）统计——被拦下的行不占额度。
8. **推送对象**：买过该品类（`member_pref` 命中）的会员优先；没有任何偏好记录的会员只参与"全店级"群发文案，不单独推送。
9. **决策留痕**：店主的确认/修改必须落 `pricing_decision`，记录 `suggested_price`、`final_price`、`operator`、`reason`；
   不接受时记 `reject_reason`——这是效果对比与"人机协同"论证的数据来源。
10. **推送计划与日志分离（v2）**：`push_task` 是计划（PLANNED/SENT），`push_log` 是发送与效果。
    预览只建计划、**绝不发送**；发送必须显式调用接口。**无任何自动发送**（推送侧禁止定时任务）。
11. **临期判定指标（v2，参考架构《临期判定》）**：`freshness = 剩余天数 ÷ 标准保质期`（0~1）；
    `estimated_sellable_days = 剩余库存 ÷ 近 7 天日均销量`；`at_risk = 预计可售天数 > 剩余天数`。
    测算口径说明走接口字段 `metricsReason`（实时计算、不落库）；落库时间见 `metrics_updated_at`。

## 4. 数据库表结构（H2 口径，同步兼容 MySQL 8）

> 约定：所有表带 `created_at`/`updated_at`；金额用 `DECIMAL(10,2)`；不用数据库方言特性（除自增与 `COMMENT` 由 MySQL 版单独提供）。

```sql
-- 4.1 商品（单品）---------------------------------------------------------
CREATE TABLE fruit_item (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  item_code     VARCHAR(32)  NOT NULL,          -- 条码/编码（公开数据里是 15 位条码）
  item_name     VARCHAR(64)  NOT NULL,
  category_name VARCHAR(32)  NOT NULL,
  unit          VARCHAR(16)  NOT NULL,          -- 份/斤/盒
  cost_price    DECIMAL(10,2) NOT NULL,         -- 参考成本价（元/单位）
  base_price    DECIMAL(10,2) NOT NULL,         -- 原价（元/单位）
  shelf_life_days INT        NOT NULL,          -- 保质期天数
  loss_rate_pct DECIMAL(5,2) NOT NULL DEFAULT 0,-- 参考损耗率%
  status        VARCHAR(16)  NOT NULL DEFAULT 'ON',  -- ON/OFF
  created_at    TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at    TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE UNIQUE INDEX uk_fruit_item_code ON fruit_item (item_code);

-- 4.2 到货批次（临期台账的核心）-------------------------------------------
CREATE TABLE fruit_batch (
  id             BIGINT AUTO_INCREMENT PRIMARY KEY,
  item_id        BIGINT       NOT NULL,
  batch_no       VARCHAR(32)  NOT NULL,
  arrive_date    DATE         NOT NULL,          -- 到货日
  expire_date    DATE         NOT NULL,          -- 到期日
  init_qty       DECIMAL(10,2) NOT NULL,         -- 到货量
  remain_qty     DECIMAL(10,2) NOT NULL,         -- 现存可售量
  cost_price     DECIMAL(10,2) NOT NULL,         -- 该批次实际进货价
  scrap_qty      DECIMAL(10,2) NOT NULL DEFAULT 0, -- 累计报废量
  status         VARCHAR(16)  NOT NULL DEFAULT 'ON_SALE', -- ON_SALE/SOLD_OUT/SCRAPPED
  created_at     TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at     TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_batch_item_expire ON fruit_batch (item_id, expire_date);
CREATE UNIQUE INDEX uk_batch_no ON fruit_batch (batch_no);

-- 4.3 定价建议 ------------------------------------------------------------
CREATE TABLE pricing_suggestion (
  id              BIGINT AUTO_INCREMENT PRIMARY KEY,
  biz_date        DATE         NOT NULL,
  item_id         BIGINT       NOT NULL,
  batch_id        BIGINT       NOT NULL,
  days_left       INT          NOT NULL,          -- 剩余可售天数
  remain_qty      DECIMAL(10,2) NOT NULL,
  original_price  DECIMAL(10,2) NOT NULL,         -- 原价（折扣基准）
  suggested_price DECIMAL(10,2) NOT NULL,
  discount_rate   DECIMAL(4,2) NOT NULL,          -- 0.50 ~ 1.00
  strategy        VARCHAR(16)  NOT NULL,          -- FIXED/RULE/MODEL
  expected_qty    DECIMAL(10,2) NULL,             -- 模型给出的期望销量
  reason          VARCHAR(255) NULL,              -- 人话理由，直接展示给店主
  created_at      TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_sugg_date_strategy ON pricing_suggestion (biz_date, strategy);

-- 4.4 定价决策（店主确认/改价，人机协同的证据）------------------------------
CREATE TABLE pricing_decision (
  id              BIGINT AUTO_INCREMENT PRIMARY KEY,
  suggestion_id   BIGINT       NOT NULL,
  suggested_price DECIMAL(10,2) NOT NULL,
  final_price     DECIMAL(10,2) NOT NULL,
  accepted        BOOLEAN      NOT NULL,          -- 是否采纳建议
  operator        VARCHAR(32)  NOT NULL,
  reason          VARCHAR(255) NULL,
  decided_at      TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 4.5 会员与偏好 ----------------------------------------------------------
CREATE TABLE member (
  id           BIGINT AUTO_INCREMENT PRIMARY KEY,
  member_no    VARCHAR(32) NOT NULL,
  nickname     VARCHAR(32) NOT NULL,
  phone_tail   VARCHAR(8)  NULL,                  -- 只存尾号，最小化个人信息
  joined_date  DATE        NOT NULL,
  push_enabled BOOLEAN     NOT NULL DEFAULT TRUE,
  created_at   TIMESTAMP   NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE UNIQUE INDEX uk_member_no ON member (member_no);

CREATE TABLE member_pref (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  member_id     BIGINT      NOT NULL,
  category_name VARCHAR(32) NOT NULL,
  buy_count     INT         NOT NULL DEFAULT 0,   -- 历史购买次数
  last_buy_date DATE        NULL,
  score         DECIMAL(6,3) NOT NULL DEFAULT 0   -- 偏好分值，供选人排序
);
CREATE UNIQUE INDEX uk_member_pref ON member_pref (member_id, category_name);

-- 4.6 时段客流（用历史成交笔数代替真实人流）--------------------------------
CREATE TABLE shop_traffic_hourly (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  stat_date     DATE     NOT NULL,
  hour_of_day   INT      NOT NULL,               -- 0~23
  order_count   INT      NOT NULL,               -- 成交笔数
  customer_count INT     NOT NULL,               -- 去重会员数（近似）
  is_peak       BOOLEAN  NOT NULL DEFAULT FALSE
);
CREATE UNIQUE INDEX uk_traffic_date_hour ON shop_traffic_hourly (stat_date, hour_of_day);

-- 4.7 推送计划（v2：计划与日志分离，plan 侧）-------------------------------
CREATE TABLE push_task (
  id           BIGINT AUTO_INCREMENT PRIMARY KEY,
  biz_date     DATE         NOT NULL,
  related_item_id       BIGINT NULL,
  related_batch_id      BIGINT NULL,
  related_suggestion_id BIGINT NULL,
  channel      VARCHAR(16)  NOT NULL DEFAULT 'IN_APP',  -- IN_APP / GROUP_TEXT
  plan_time    TIMESTAMP    NOT NULL,                   -- 计划发送时间（高峰前 30~60 分钟）
  reason       VARCHAR(128) NULL,                       -- 为什么选这个时间/人群
  audience_rule VARCHAR(128) NULL,
  target_count INT          NOT NULL DEFAULT 0,
  title        VARCHAR(64)  NOT NULL,
  content      VARCHAR(512) NOT NULL,
  status       VARCHAR(16)  NOT NULL DEFAULT 'PLANNED', -- PLANNED/SENT/CANCELLED
  created_at   TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  sent_at      TIMESTAMP    NULL
);

-- 4.7b 推送日志（v2：发送与效果归因）----------------------------------------
CREATE TABLE push_log (
  id           BIGINT AUTO_INCREMENT PRIMARY KEY,
  task_id      BIGINT       NOT NULL,
  member_id    BIGINT       NULL,                 -- NULL 表示群发文案（不针对个人）
  sent_at      TIMESTAMP    NOT NULL,
  opened       BOOLEAN      NOT NULL DEFAULT FALSE,
  opened_at    TIMESTAMP    NULL,
  converted    BOOLEAN      NOT NULL DEFAULT FALSE,
  converted_at TIMESTAMP    NULL,
  related_sale_id BIGINT    NULL,                 -- 归因命中的销售记录
  convert_window_hours INT  NULL,                 -- 归因窗口（默认 3 小时）
  skip_reason  VARCHAR(32)  NULL                  -- 限频/静默/退订
);

-- 4.8 销售回流 ------------------------------------------------------------
CREATE TABLE sales_record (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  biz_date      DATE         NOT NULL,
  sale_time     TIMESTAMP    NOT NULL,
  item_id       BIGINT       NOT NULL,
  batch_id      BIGINT       NULL,
  quantity      DECIMAL(10,2) NOT NULL,
  unit_price    DECIMAL(10,2) NOT NULL,
  is_discount   BOOLEAN      NOT NULL DEFAULT FALSE,
  is_return     BOOLEAN      NOT NULL DEFAULT FALSE,
  source        VARCHAR(16)  NOT NULL DEFAULT 'REAL'  -- REAL/SIM（仿真数据回流时标记）
);
CREATE INDEX idx_sales_date_item ON sales_record (biz_date, item_id);

-- 4.9 策略日统计（效果看板直接查这张表）------------------------------------
CREATE TABLE strategy_daily_stat (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  biz_date      DATE         NOT NULL,
  strategy      VARCHAR(16)  NOT NULL,            -- FIXED/RULE/MODEL
  sold_qty      DECIMAL(12,2) NOT NULL,
  scrap_qty     DECIMAL(12,2) NOT NULL,
  revenue       DECIMAL(12,2) NOT NULL,
  cost          DECIMAL(12,2) NOT NULL,
  gross_profit  DECIMAL(12,2) NOT NULL,
  scrap_rate    DECIMAL(6,4) NOT NULL,            -- 损耗率
  stockout_rate DECIMAL(6,4) NOT NULL DEFAULT 0
);
CREATE UNIQUE INDEX uk_stat_date_strategy ON strategy_daily_stat (biz_date, strategy);
```

**MySQL 8 差异**：`BOOLEAN` → `TINYINT(1)`；`AUTO_INCREMENT` 写法保留；`TIMESTAMP DEFAULT CURRENT_TIMESTAMP` 保留；`CREATE INDEX` 保留。建表脚本按方言分文件：`db/schema-h2.sql`（开发/演示）、`db/schema-mysql.sql`（答辩/部署说明），字段顺序与含义必须一致。

**契约稳定性约定**

- 路径与字段名冻结后，前端可以并行开发；新增字段属兼容变更，删除/改名必须三方同步。
- 所有日期用 `yyyy-MM-dd`，时间用 `yyyy-MM-dd HH:mm:ss`，时区 GMT+8。
- 分页统一 `page`（从 1 开始）+ `size`，返回 `total`、`records`。

## 6. 配置项（`application.yml`）

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `app.pricing.active-strategy` | `rule` | 当前生效策略（FIXED/RULE/MODEL），评测脚本会逐一覆盖 |
| `app.pricing.near-expiry-days` | `2` | 临期阈值 |
| `app.pricing.fixed-discount` | `0.70` | FIXED 策略使用的固定折扣档 |
| `app.pricing.pressure-qty-threshold` | `20` | 存量压力阈值：现存超过该值再降一档 |
| `app.pricing.model-file` | `./data/seed/pricing_model.json` | MODEL 策略读取的 Python 产物；缺失时回退 RULE 并在 reason 里说明 |
| `app.pricing.model-fallback-to-rule` | `true` | 模型产物缺失/未命中时是否回退规则版 |
| `app.pricing.min-discount-rate` | `0.60` | **v2** 最低折扣线：任何策略与店主改价都不得低于该价格比 |
| `app.pricing.max-adjust-per-day` | `2` | **v2** 同一批次每天最多调价次数（生成与改价都算） |
| `app.scan.enabled` | `true` | **v2** 只读临期扫描开关（只写派生指标，不产生决策） |
| `app.scan.cron` | `0 0 * * * *` | **v2** 扫描周期（默认每小时整点） |
| `app.push.daily-limit-per-member` | `2` | 单会员每日推送上限（按 `push_log` 真正送达行统计） |
