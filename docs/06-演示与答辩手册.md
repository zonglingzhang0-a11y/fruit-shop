**答辩口径提醒（第 ⑦ 步最容易被追问）**

- 不要说"MODEL 全面胜出"：对 FIXED，MODEL 是 **0/20 个种子毛利更高**，它付出了毛利代价。
- 正确说法：MODEL 在**清货效率**上优于经验规则，且对 RULE 在毛利上 20/20 全胜、稳定性也更好（毛利标准差 4,024 vs RULE 3,059 属同一量级，逐种子全胜更强）。
- 被问"那为什么不直接用 RULE"时：RULE 的 4.82% 损耗率是**用 18,944 元毛利换来的**。店主未必愿意为多降 2.8pp 损耗牺牲近 40% 的毛利；
  MODEL 给出的是更省的中间档，且它的折扣档是数据算出来的、带理由，可解释也可改。

**演示纪律**：任何被问到的数字，先回答"这个来自 X 脚本，我可以现在就跑给你看"，不要背数字。

> **第 ⑦ 步是本项目最容易被低估的亮点**：团队发现并如实报告了"打折是亏的"，还给出了正确的替代评价标准。这比强行宣布"模型全面胜出"可信得多，也是答辩时最能体现方法自觉的地方。

## 2. 预设问答（答辩最可能被问的 8 个问题）

| 问题 | 回答要点 | 现场证据 |
| --- | --- | --- |
| **数据是编的吧？结论自己造数据自己打分？** | 分两层：① 校准用**真实公开数据**（87.8 万条）；② 评测在仿真器上做，**结论明确标注为 B 类证据**，只说明"在给定假设下更优"。 | `docs/00` §6.1、`docs/02` §1 |
| 你的参数是不是为了结论调出来的？ | 做了参数敏感性分析（含价格敏感度 ±30% 扰动），扰动下排序不变。 | `docs/02` 敏感性一节 |
| 定价算法为什么不做强化学习？ | 数据量与可解释性都不支持；店主需要知道"为什么打 8 折"，回归+候选档枚举足够且可解释。 | `docs/03` |
| 公平性怎么保证？会不会"杀熟"？ | 系统对所有人是同一个价；会员偏好只决定**推送给谁**，不决定**卖多少钱**。 | `docs/05` |
| 个人信息合规吗？ | 只存会员尾号与品类偏好，不采集人脸/位置；推送有频次上限与退订。 | `docs/05` |
| 蔬菜数据能代表水果吗？ | 不能，所以只借"形状"（时段分布、价格—销量方向），不借"量级"；单品参数按水果保质期重设，跨业态差异写在文档里。 | `docs/02` §1.3 |
| 系统能自动改价吗？ | 不能，这是刻意的：系统只给建议，`pricing_decision` 记录店主是否采纳。 | `docs/01` §3 规则 7 |
| 真实门店能用吗？ | 现在不能直接上生产：批次录入负担、无真实流水、无支付对接。已列为局限性并给出演进路径。 | `docs/00` §6 |

## 5. 已知局限（必须主动说，不要等着被问）

1. **评测在仿真器上完成**：结论依赖仿真假设；真实门店数据缺失（仅作为后续工作）。
2. **批次粒度简化**：按品类+到货日，而非逐箱；真实店主录入负担与准确性未验证。
3. **推送环节未纳入评测**：只验证了链路与限频合规，没有做推送带来的增量收益 A/B 实验。
4. **需求侧事实待访谈**：`docs/04` §3 有 24 行标为 C 类（待访谈验证），包括价格牌做法、微信群规则、以及"是否有人专门等降价"。
5. **跨业态迁移**：时段形状借用真实蔬菜门店数据，绝对量级由仿真器重标定（B 类假设）。
